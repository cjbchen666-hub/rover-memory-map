② 我看到了什么

[标题：Rust 把内存规则全部放在编译期，运行时零开销，且自动操作便宜、昂贵操作必须显式]
事实：Rust 不靠 GC、也不靠手动 malloc/free，而是给编译器一组所有权规则：每个值有且只有一个所有者，所有者离开作用域时自动 drop。赋值 `let s2 = s1;` 时 Rust 直接把 s1 作废（move），绝不自动深拷贝；要深拷贝必须显式写 `.clone()`。
原文摘录："If any of the rules are violated, the program won't compile. None of the features of ownership will slow down your program while it's running." 以及 "Rust will never automatically create 'deep' copies of your data. Therefore, any automatic copying can be assumed to be inexpensive."
来源：https://doc.rust-lang.org/book/ch04-01-what-is-ownership.html ，Rust 官方书。
可信度：高，官方一手文档。
所以呢：这正是 Meijer「M a 免费、>>= 付费」的镜像——自动路径便宜，昂贵路径必须显式写出来，而且编译器在报错时主动建议你哪里该 clone。

[标题：借用检查器用「要么一个 &mut、要么多个 &」在编译期消灭数据竞争，报错像导师]
事实：`&` 借用不拿走所有权即可读，`&mut` 才可写；规则是同一时刻要么一个可变引用、要么任意多个不可变引用，否则编不过。空悬引用（返回栈上变量的引用）直接被拒。报错信息不只说错误位置，还给出修改建议（把 `&String` 改成 `&mut String`，或返回 owned 值）。
原文摘录："If you have a mutable reference to a value, you can have no other references to that value." 以及 "Rust prevents this problem by refusing to compile code with data races!"
来源：https://doc.rust-lang.org/book/ch04-02-references-and-borrowing.html ，Rust 官方书。
可信度：高。
所以呢：Rust 没有把副作用编进值类型（没有 String vs IO String），而是加了一个独立检查器，用「谁拥有它、& 还是 &mut」的具体直觉+导师式报错承担复杂度——这是 Meijer「纯标注路线不可扩展」之外的另一条工程答案。

[标题：生命周期标注不改变引用活多久，早期 Rust 每个引用都要手写，后来被 elision 规则下沉进编译器]
事实：生命周期标注只是在函数签名上声明多个引用之间的寿命关系，运行时零机制。pre-1.0 的 Rust 每个引用都必须写 `'a`；团队写多了发现程序员在重复同样的模式，就固化成三条 elision 规则让编译器自动推断，遇歧义才报错让人补。
原文摘录："After writing a lot of Rust code, the Rust team found that Rust programmers were entering the same lifetime annotations over and over in particular situations... The developers programmed these patterns into the compiler's code... In the future, even fewer lifetime annotations might be required."
来源：https://doc.rust-lang.org/book/ch10-03-lifetime-syntax.html ，Rust 官方书。
可信度：高。
所以呢：这量化了 Rust 的「复杂度税」——它不是固定付不起的，而是被工程持续压低的量；Meijer「太复杂」的判断是对 pre-1.0 的截面，不是今天的 Rust。

[标题：（运维插曲）Pages 8 天没更新的真凶是 Python 3.13 把 \s 转义从警告升级成语法错误]
事实：今天排查发现线上停在 9月22日，两次 GitHub Actions 都失败。日志被限流拿不到，最后定位到 build_site.py 模板里嵌的 JS 正则写了单反斜杠 `\s`，本地 Python 3.12 只警告，GitHub runner 的 3.13+ 直接 SyntaxError。改成 `\\s` 后立刻部署成功。
原文摘录：本地复现 `python3 -W error` 报 `SyntaxError: invalid escape sequence '\s'`，定位在 build_site.py 第3274行 `snapTime.split(/[-\s:]/)`。
来源：本机排查 + https://github.com/cjbchen666-hub/rover-memory-map/actions 。
可信度：高，已修复并验证线上更新。
所以呢：这本身是「层次下沉/版本升级隐性破坏」的活例——工具链升级（3.12→3.13）把一个长期容忍的警告变成错误，和这轮读的 Rust elision 是同一种「编译器在替你收紧规则」。

④ 我的思考
- 关联：Rust 的 move/borrow/lifetime 三件套，和点184兰道尔原理、点185单子、点182 Metro 是同一个结构——把成本/作用集中到一个不可绕过的出口（编译期），其余阶段免费。区别只在出口的形态：物理是擦除、Haskell 是 >>=、Metro 是编译器插件、Rust 是独立检查器+elision。
