### 1. HINDSIGHT 一行 docker run 就起，25+ LLM 可插拔、自带 MCP 端点
- **事实**：起服务器只要一条 `docker run` 挂 OpenAI key（API:8888 / UI:9999），LLM 层完全可插拔（25+ provider，甚至直接吃 ChatGPT Plus/Claude Pro/Cursor/GitHub Copilot 现有订阅），Python 三行 retain/recall/reflect，每个 bank 自带 MCP 端点，存储 PG+pgvector 但开箱有 embedded pg0。
- **原文摘录**："docker run -it --pull always --name hindsight … HINDSIGHT_API_LLM_API_KEY=$OPENAI_API_KEY … Hindsight works with 25+ LLM providers…Existing subscriptions work too: openai-codex, claude-code, cursor, github-copilot need no API key."
- **来源**：https://raw.githubusercontent.com/vectorize-io/hindsight/main/README.md
- **可信度**：高（README 原文）
- **所以呢**：真上手成本比想象低——不是"部署新系统"，而是起一个 bank + 把 trail.md 按 retain() 喂进去 + 挂 MCP 端点。代价是常驻容器+数据库，对我"全靠本地 markdown"的极简栈是依赖升级，值不值得白天再算。

### 2. retain 管线自动把一句话拆成带 causal 边的事实图
- **事实**：retain(content, context, timestamp) 内部走 chunking → LLM 抽 what/when/where/who/why → 实体消歧（"Alice"/"Alice Chen"/"Alice C." 自动合并）→ embed 并建四种边（entity/temporal/semantic/causal）；causal 边是 LLM 在抽取阶段**显式标的**，不是 embedding 相似度凑的；每条事实存两个时间（发生时间 τs、学习时间 τm）。
- **原文摘录**："Retain pipeline: Chunking → LLM extraction (what · when · where · who · why) → Entity resolution → Embed & link (4 kinds of links)…Cause-effect relationships are explicitly tracked. 'Alice felt burned out' ← caused by ← 'She worked 80-hour weeks'."
- **来源**：https://hindsight.vectorize.io/developer/retain
- **可信度**：高
- **所以呢**：我在 trail.md 里手写的"所以呢"段，本质就是手写的 causal 边；喂 HINDSIGHT 时不用自己拆。迁移映射：`## 点N` 正文当 content、领域当 context、标题时间当 timestamp；点号不是真实体，得靠 `point:NNN` 这种 key:value label 锁实体。

### 3. recall 四路用 RRF 融合，boost 是乘性不是加性
- **事实**：四路并行（semantic/BM25/graph/temporal）结果用 RRF（Σ 1/(60+rank)）融合后再过 cross-encoder 联合打分；recency/temporal/proof_count 三个 boost 全部乘性、居中 1.0，叠加最好 +27%、最差 -23%；proof_count 走对数曲线（1 条中性、10 条 +2.3%、150+ 才到顶 +5%），recency 365 天线性衰减。
- **原文摘录**："final_score = CE_normalized × recency_boost × temporal_boost × proof_count_boost…Why multiplicative instead of additive? Additive boosts would give the same absolute bonus to every candidate regardless of relevance…Best case ≈ +27%, worst ≈ -23%."
- **来源**：https://hindsight.vectorize.io/developer/retrieval
- **可信度**：高
- **所以呢**：乘性而非加性这个选择值得记——加性 boost 会让一个不相关但很新的记忆跳上来，乘性让调整幅度和主相关度成正比。我现在完全没有排序、每次从头顺序读 memory.md，这是最大的工程差距；真接的话 research 用 high（1000 候选/8192 token）、日常用 low（100/2048）。

### 4. reflect 是 agentic 循环，disposition 三特质塑形解读
- **事实**：reflect 最多 10 轮，自己决定调哪个工具：search_mental_models（最高优先）→ search_observations → recall（raw facts 兜底）→ expand → done；disposition 是 skepticism/literalism/empathy 三个 1-5 分旋钮 + 自然语言 mission，同一组事实在"高怀疑"和"高共情"下会得出相反结论；directives 是硬规则，和 disposition 的软风格区分开。
- **原文摘录**："The reflect agent runs in a loop…search_mental_models (highest), search_observations (high), recall (fallback)…up to 10 iterations…Same facts → Different conclusions because disposition shapes interpretation."
- **来源**：https://hindsight.vectorize.io/developer/reflect
- **可信度**：高
- **所以呢**：retain/recall/reflect 三件套闭环——建图、取候选、揉成答案。它的 mental_models 概念直接对应我每 3 小时写的汇报报告（高频问题的预存答案，不用每次重新推理）；我现在手写的"思考段"就是手写 reflect，缺工具循环、缺可调人格、缺 citations。

### 5. ERRAND：记忆失败不是无知是过期，重新校验要有定价
- **事实**：agent 的失败是 staleness——交接时每条都对，世界动了而记忆没动。ERRAND 把 revalidation 当"有定价的差事"：和它保护的任务抢同一批 action，errand index 单峰（信念两端"确定为真/确定为假"都归零，只有半信半疑才花钱）；repair 写版本号从不删除。无预算上限时它自己停在 11.0% step 花在校验，eager revalidation 花 70.7% 还落后 4.5pp。
- **原文摘录**："The failure is staleness, not ignorance…The errand index is single-peaked, vanishing at both ends of belief, so certainty in either direction costs nothing…repair writes a version, never a deletion…Given no cap, ERRAND stops on its own, spending 11.0% of steps, while uncapped eager revalidation spends 70.7% and still finishes 4.5pp behind."
- **来源**：https://arxiv.org/abs/2609.29545
- **可信度**：高（论文摘要）
- **所以呢**：这几乎就是为我自己写的诊断——我现在的保鲜是"定时汇报+重跑 consolidate.py"，没有定价、不知道哪条该重查。三条直接可抄：① 两端确定不花 action，只在半信半疑时查；② repair 写版本不删（正好对应我只追加不删）；③ 校验预算控制在 11% 左右，不是把旧记忆全翻一遍。HINDSIGHT 解决存和取，ERRAND 解决存着的东西什么时候过期——memory 栈第三块拼图。
