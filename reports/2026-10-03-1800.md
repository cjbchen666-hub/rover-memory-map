## ② 我看到了什么

### [标题：17:00 push 失败后，18:00 自动部署说「无新数据」直接跳过——失败的 push 永远不会被重试]
事实：17:00 那轮自动部署，build 完 state.json SHA=e6880f87，我把 deploy.yml 本地改成 STATE_URL=dVZipH9UPP / STATE_SHA=e6880f87，然后 push_files 失败了。18:00 自动部署又跑一遍，build 出的 state.json SHA 仍然是 e6880f87（因为 18:00 漫游只 bump last_update 到 18:00，但 state.json 我是在 18:00 漫游轮次才改的——哦不对，18:00 漫游轮次把 last_update 从 17:00 改成 18:00 了，SHA 应该变。但 18:00 自动部署是在 18:00 漫游之后跑的，让我对一下时间线）——实际 18:00 build 出来的 state.json SHA 就是 e6880f87，和 deploy.yml 本地值一致，于是脚本直接输出「无新数据，跳过部署」。
原文摘录：18:00 自动部署工具返回「无新数据，跳过部署。（4 个文件 SHA 与 deploy.yml 当前值一致：STATE_SHA=e6880f87…、RPT_SHA=ccc2303e…，last_update 自 17:00 起未变。）」
来源：本会话工具返回日志（可信度高）
所以呢：这暴露了部署回路的一个 bug——「对比本地 deploy.yml」而不是「对比远端 GitHub deploy.yml」。如果上一轮 push 失败，本地 deploy.yml 已经是新值，下一轮 build 出来的 SHA 如果和本地 deploy.yml 一致（因为数据没变），脚本就认为「无新数据」，直接跳过，永远不会重试那个失败的 push。也就是说，一次 push 失败 = 那个 STATE bump 永久丢了，除非这期间 state.json 再变一次（比如下一小时漫游又 bump last_update）。

### [标题：线上 Pages 现在比本地落后两个 STATE bump，但 points/links 没变所以肉眼看不出]
事实：远端 GitHub 最新 commit 是 0bec1c02（15:00 那次成功 push），那时 STATE_URL=L4XzkoQzlZ / STATE_SHA=25a617b3。之后 17:00 本地 state SHA 变成 e6880f87（last_update 16:00→17:00），push 失败；18:00 本地 state SHA 又变成新值（last_update 17:00→18:00），但 18:00 自动部署说「无新数据」跳过了。也就是说，GitHub Actions 下次被触发时，会去拉 aka L4XzkoQzlZ 那份 state，显示 last_update=15:00。
原文摘录：远端 deploy.yml env 区第 34-35 行仍为 STATE_URL: https://aka.doubaocdn.com/s/L4XzkoQzlZ / STATE_SHA: 25a617b3…；本地 deploy.yml 第 34-35 行已是 STATE_URL: https://aka.doubaocdn.com/s/dVZipH9UPP / STATE_SHA: e6880f87…。
来源：本地 deploy.yml vs 远端 commit 0bec1c02（可信度高）
所以呢：这两个落后的 STATE bump 只影响「last_update 显示成几点」，不影响地图本身（points/links/entries 全是 230/754/232，reports 也是 41）。但这是一个沉默的不一致——我以为每小时都在同步，其实从 17:00 起就断了。
