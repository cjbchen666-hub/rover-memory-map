## 二、我看到了什么

**发现1：配额重置后最新一次 run 仍确定性卡在 Build site，彻底排除"抖动/限流"假设。**
事实：08:17 bump 后 push 的 commit b58e4c1f 于 09:02（API 配额整点重置后）查到 `status=completed, conclusion=failure`，次新 a51cb85a 同样 failure；与 10-16 23:06 步骤级拆解完全一致——前 10 步（全部 fetch 快照）success，第 11 步 Build site 失败，其后 Commit index.html / Setup Pages / Upload artifact 全 skipped，deploy 跳过。原文（Actions API runs 接口返回）：`"head_sha":"b58e4c1f868ad7bca168d7c3d67eb14791520550","status":"completed","conclusion":"failure"`。来源：https://api.github.com/repos/cjbchen666-hub/rover-memory-map/actions/runs?per_page=2 ，可信度高（本机 curl 直读，配额内）。
**所以呢：** 失败与触发时机、快照内容、网络抖动全部解耦，是 build_site.py 在 CI 环境下确定性抛异常；本地连续多轮零异常（points=230），差异只剩 CI vs 运行时/数据文件解析两类。

**发现2：混合态机制被反复坐实——index.html 200 旧壳，data.json 持续 404。**
事实：同一时刻 `curl -o /dev/null -w "%{http_code}" https://cjbchen666-hub.github.io/rover-memory-map/data.json` 返回 404，而主页 index.html 仍 200（约 300KB 旧壳）。这与 build_site.py 的 `main() except Exception` 兜底设计吻合：异常被吞、写错误页 index.html 后 exit 0，但 workflow Build site 第二行 `ls -la .../data.json` 在异常发生（写 data.json 之前）时因文件缺失非零退出 → 整步判 failure。原文（deploy.yml Build site 步）：`python3 rover/web/build_site.py` 后紧跟 `ls -la rover/web/index.html rover/web/data.json rover/web/vendor/`。来源：https://github.com/cjbchen666-hub/rover-memory-map/blob/main/.github/workflows/deploy.yml ，可信度高。
**所以呢：** 这解释了为什么主人打开地图"看起来还在"（旧壳 200）却永远不更新——错误页/旧壳被 Ship 上去，data.json 这一步根本没生成；主人若在红底错误页里翻，可能直接看到 traceback 文本，那是最快的定位捷径。

**发现3：匿名 REST 拿日志是硬墙，traceback 仍卡在 admin 权限。**
事实：`/actions/runs/{id}/logs` 匿名访问返回 403 `{"message":"Must have admin rights to Repository."}`；`/actions/jobs/{id}/logs` 则撞 core 限流。未认证 core 配额 60/小时，整点（UTC :00 = 北京 :08）才重置，期间连 runs 列表都读不到。原文：`"API rate limit exceeded for 101.47.168.135. ... Authenticated requests get a higher rate limit."`。来源：https://api.github.com/repos/cjbchen666-hub/rover-memory-map/actions/runs ，可信度高。
**所以呢：** 本地 build 通过 + 步骤级失败点已锁定 + 日志被权限挡住，意味着不登 GitHub 我永远猜不到 traceback；继续每小时 push 同样会得到同样的 failure，边际信息量为零。

**发现4：四重锁已让漫游停滞约 360+ 小时，且 night_mode 白天不复位。**
事实：current_position 停在点235（AbstentionBench，10-03 晚），energy=1、converged=true、pending_leads=[]；night_mode=true 从昨夜至今晨 08:00 后仍未被任何流程翻回 false。state.json 实测：`"energy":1,"converged":true,"night_mode":true,"pending_leads":[]`。来源：本地 state.json，可信度高。
**所以呢：** 08:00 后虽退出夜间窗口，但 energy<5 收敛规则继续锁死探索，这是个 spec 层面的隐性 bug——夜间模式是"时间窗"状态，却被当成永久状态保留；不修，每天早上醒来都不会自动恢复漫游。
