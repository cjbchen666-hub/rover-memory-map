## ② 我看到了什么

### 发现1：三路写通道在 git log 里首次同框，时间戳互相咬合
事实：拉取 `https://api.github.com/repos/cjbchen666-hub/rover-memory-map/commits?per_page=12`，最近 12 条 commit 出现三种 message：`deploy: auto update snapshot URLs (hourly)`（本部署员 push）、`build(index.html): auto rebuild from Rover data [skip ci]`（CI 回写根 index.html）、`sync rover state.json heartbeat 2026-10-20 08:17`（后台数据同步 cron 直推）。例如 09:01 轮：8c1b01d2 于 01:02:04Z 我的 push，060ba3cb 于 01:02:24Z CI 回写，相隔仅 20 秒；920cde2b 于 00:23:30Z 后台 sync 直推 08:17 心跳。
原文摘录：`"build(index.html): auto rebuild from Rover data [skip ci]"`、`"sync rover state.json heartbeat 2026-10-20 08:17"`、`"deploy: auto update snapshot URLs (hourly)"`。
来源URL：https://api.github.com/repos/cjbchen666-hub/rover-memory-map/commits?per_page=12
可信度：高（GitHub API 实时返回）。
所以呢：之前汇报说"两条写通道"，实际是三条——本 hourly 快照通道、CI 回写通道、后台 sync 直推通道。后台 sync 不经过我上传的 aka 快照，而是直接把 state.json 推到 repo 根，它的心跳时间（05:17/06:17/08:17）正好对应我每轮拾取的 last_update，说明磁盘 state.json 与 repo 根 state.json 是同一个文件被两条 cron 分别写。

### 发现2：根 index.html 回写副本已追平最新 snapshot，体积 1,726,676 字节
事实：curl 拉 `https://raw.githubusercontent.com/cjbchen666-hub/rover-memory-map/main/index.html`，HTTP 200、size_download=1,726,676，内嵌 `snapshot_time":"2026-10-20 08:17"`。对比 10-19 23:00 轮记录的 1,719,772 字节，一夜之间增大约 6.9KB，snapshot 从 21:27 推进到 08:17。
原文摘录：`snapshot_time":"2026-10-20 08:17"`；`size=1726676 http=200`。
来源URL：https://raw.githubusercontent.com/cjbchen666-hub/rover-memory-map/main/index.html
可信度：高（raw 通道实测）。
所以呢：23:00 轮说根 index.html 是"活着的第二发布通道"，现在它不仅活着，而且每轮 CI 都把最新 HTML 产物回写进 repo 根，与 Pages 部署只差一个 Pages 构建延迟（约 20 秒）。这意味着即使 GitHub Pages 服务整体故障，raw 上的根 index.html 仍是一份完整可离线打开的记忆地图快照。

### 发现3：web/vendor 在仓库里并不存在，"local vendor" 实为每次 CI 现拉 jsdelivr
事实：GET `https://api.github.com/repos/cjbchen666-hub/rover-memory-map/contents/web/vendor` 返回 404 Not Found；列 repo 根目录只有 `.github/ reports/` 两个目录，没有 `web/`。deploy.yml 第 118-124 行注释写 "Fetch ECharts (local vendor, P0-1)"，但实际动作是 `curl ... https://cdn.jsdelivr.net/npm/echarts@5.5.0/dist/echarts.min.js -o rover/web/vendor/echarts.min.js`，失败时只 echo `WARNING: echarts download failed, map will not render`。
原文摘录：`{"message": "Not Found", "documentation_url": "...", "status": "404"}`；`echo "WARNING: echarts download failed, map will not render"`。
来源URL：https://raw.githubusercontent.com/cjbchen666-hub/rover-memory-map/main/.github/workflows/deploy.yml
可信度：高（API 404 + deploy.yml 原文）。
所以呢：注释里的 "local vendor" 名不副实——ECharts 本体没有提交进 repo，每次 CI 都从 jsdelivr 现拉。jsdelivr 一次抖动或 GitHub Actions 出口 IP 被限，整张图就只渲染空壳 HTML 而不报错。要真正离线，应把 echarts.min.js 作为 vendor 产物提交进 repo 或走 actions/cache。
