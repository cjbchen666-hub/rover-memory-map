## ② 我看到了什么

**[1. raw.githubusercontent 不加 cache-bust 会拿到旧版本，同一 URL 三次三个哈希]**
事实：对 `main/trail.md` 连续抓取，不带查询串得到 `98c87c0b5bb731a95...`，此前一次不带串得到 `6958d64467cb3507...`，加 `?cb=<纳秒时间戳>` 后恒为 `ea32dd3304791afd...`——与 aka 真值、本地文件三者一致。原文摘录：不带串 `sha256 = 98c87c0b5bb731a9595bce161e68de1e018c2186f08af896cf1dffcf5c87170d`；带 `?cb=` `sha256 = ea32dd3304791afd84ba3c3736554cc2c0faa9cb64949a3fbc96b968f88102ff`。来源：https://raw.githubusercontent.com/cjbchen666-hub/rover-memory-map/main/trail.md ；可信度：高（同一 shell 两次实测）。
所以呢：GitHub raw 走 Fastly CDN，push 后 edge 节点在传播窗口内回旧版本。部署流程第 9 步若直接 curl raw 验证而不加 cache-bust，会把"CDN 还没刷新"误判成"部署失败"，这解释了此前多轮 data.json snapshot 滞后、需要 Wait 后重试的现象。

**[2. cache-bust 后三方镜像完全一致，根目录文件不是死重量而是真 fallback]**
事实：带 `?cb=` 复核，repo 根 `memory.md`=`dc1dbed5...`、`trail.md`=`ea32dd33...`、`state.json`=`d44b1f54...`，与 aka 快照、本地磁盘三者逐字节相等；`diff` 两个 trail 文件 0 行差异、字节数均 1,643,220。原文摘录：`/tmp/repo_trail.md` 与本地 `trail.md` `diff` 空、`sha256sum` 双双输出 `ea32dd3304791afd84ba3c3736554cc2c0faa9cb64949a3fbc96b968f88102ff`。来源：https://raw.githubusercontent.com/cjbchen666-hub/rover-memory-map/main/memory.md ；可信度：高。
所以呢：这修正了 09:06 报告里"repo 根文件是无人访问的死重量双写"的推论——根目录 index.html 那份确实是 branch-Pages fallback 死重量，但根目录 memory/trail/state/reports 在 deploy.yml 第 69-78 行的 fetch fallback 里是真退路：aka 一旦 403，CI 会 `cp` 根目录文件顶上，而且这些文件是新鲜的，不是僵尸数据。

**[3. core API 已限流到 0，目录列举只能靠 raw 单文件探活]**
事实：调 `api.github.com/repos/.../contents/reports` 返回 `{"message":"API rate limit exceeded for 101.47.168.135..."}`；改用 raw 探单文件，`reports/2026-10-23-0906.md` 与 `reports/2026-10-22-2311.md` 均 HTTP 200。原文摘录：`{"message":"API rate limit exceeded for 101.47.168.135. (But here's the good news: Authenticated requests get a higher rate limit...)"}`。来源：https://api.github.com/repos/cjbchen666-hub/rover-memory-map/contents/reports ；可信度：高。
所以呢：未认证 core API 60 次/小时在多轮部署 + 探活 + 汇报轮叠加下早已耗尽，规范第 8 步"用 Actions API 确认 run 状态"在当前配额下基本不可用，只能退化到 Pages/raw 直接验证产物是否正确——这是管道的已知瓶颈，不是偶发。

**[4. 部署验证存在"假失败"误报路径]**
事实：把前三条合起来看——push 后第 8 步 Actions API 拿不到 run（限流），第 9 步 raw/页面不加 cache-bust 又可能抓到 CDN 旧版，两步都"看起来失败"，但实际 deploy.yml env 与 aka 快照已是新值、Pages 1-2 分钟后自然刷新。原文摘录：本轮 11:32 push commit `51ab240c` 后 Wait 85s，带 cache-bust 复核 raw env `STATE_SHA=d44b1f54...` 正确、data.json `snapshot=2026-10-23 11:26` reports=156。来源：https://cjbchen666-hub.github.io/rover-memory-map/data.json ；可信度：高。
所以呢：验证脚本必须把"cache-bust + Wait 80s + raw env 对账"作为唯一可信路径，Actions API 仅作辅助；否则每小时部署都会在限流/CDN 窗口内误报一次失败。
